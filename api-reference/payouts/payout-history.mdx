---
title: "Payout history"
description: "This endpoint is used to retrieve the paginated list of all payouts."
api: "GET /payouts/all"
---

### Headers

<ParamField header="X-API-Version" type="string" default="1.2" required>
  The API version to use. Supported versions are `1.1` and `1.2`.
</ParamField>

### Query Parameters

<ParamField query="page" type="number">
  The page number for pagination. Default is 1.
</ParamField>

<ParamField query="limit" type="number">
  The number of records per page. Default is 5.
</ParamField>

### Response Body

| Field | Type | Description |
|---|---|---|
| `status` | number | The HTTP status code of the response. |
| `data`array | array | List of payout records. |
| ↳`worker_id` | string | The unique identifier for the worker. |
| ↳`worker_name` | string | The full name of the worker. |
| ↳`payout_id` | number | The unique ID of the payout. |
| ↳`payout_amount` | string | The payout amount. |
| ↳`currency` | string | The currency of the payout (e.g. "AUD"). |
| ↳`reference` | string | The reference note associated with the payout. |
| ↳`date` | string | The date and time of the payout in ISO 8601 format. |
| ↳`message` | string | The payout status description or status message. |
| ↳`status` | string | The current status of the payout (e.g., "Paid", "Pending", "Processing", "Failed", "Cancelled"). |
| ↳`transfer_id` | string | The unique identifier for the processed transfer. |
| `pagination`object | object | Pagination metadata. |
| ↳`page` | number | The current page number. |
| ↳`limit` | number | The limit of items per page. |
| ↳`total_records` | number | The total number of payout records matching the request. |
| ↳`total_pages` | number | The total number of pages. |
| ↳`has_next_page` | boolean | Indicates if a next page of records exists. |
| ↳`has_previous_page` | boolean | Indicates if a previous page of records exists. |

### Response Codes

| Code | Description |
|---|---|
| 200 | If the request is successful, the list of payouts and pagination metadata is retrieved. |
| 400 | Bad Request. Invalid parameter format. |
| 401 | Unauthorized. Missing or invalid credentials. |
| 500 | Internal Server Error. |

<RequestExample>

```bash cURL
curl -X GET https://qa-payments.mygigsters.com.au/api/v1/payouts/all?page=1&limit=5 \
  -u "YOUR_UUID:YOUR_SECRET" \
  -H "X-API-Version: 1.2" \
  -H "Content-Type: application/json"
```

</RequestExample>
