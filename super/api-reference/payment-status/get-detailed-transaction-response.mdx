---
title: "Get detailed transaction response"
description: "Identical to GET /v1/payments/response/transaction/:transactionId in every way, except the errorDetails object includes one additional field: errorDetailedDescription."
api: "GET https://qa-super.mygigsters.com.au/v1/payments/detailed-response/{transactionId}"
---

Use this endpoint when you need richer context for error investigation or when displaying verbose information to operations teams.

### What's Different

Only the `errorDetails` object differs:

**Standard response** (`/response/transaction/:transactionId`):

```json
{
  "errorSeverityCode": "ERROR",
  "errorDescription": "No longer a member of superannuation entity"
}
```

**Detailed response** (`/detailed-response/:transactionId`):

```json
{
  "errorSeverityCode": "ERROR",
  "errorDescription": "No longer a member of superannuation entity",
  "errorDetailedDescription": "Please check the USI to confirm that the number is correct. See {url} for more information."
}
```

All other fields — `responseType`, `refundData`, `transactionFund`, `memberRequest`, `employerRequest` — are identical between the two endpoints.

### When to Use Which

| Endpoint | Use case |
|---|---|
| `/response/transaction/:transactionId` | Automated reconciliation and status checks |
| `/detailed-response/:transactionId` | Debugging, or displaying verbose error details to users |

### Response Structure

See `GET /v1/payments/response/transaction/:transactionId` for the full response structure. The only difference is `errorDetails` includes `errorDetailedDescription`.

```json
{
  "identifier": {
    "transactionId": { "value": "34623710896_20250115_001" },
    "timeInUTC": 1737000000000
  },
  "responseTransaction": [
    {
      "transactionFund": {
        "fund": { "usi": "STA0100AU", "fen": "FEN123" },
        "smsf": null
      },
      "employerResponseDetails": {
        "employerRequest": { "..." : "..." },
        "employerResponse": {
          "responseType": "EMPLOYER_REFUND",
          "refundData": {
            "employerPaymentPRN": "PC190716-000001340",
            "employerRefundPaymentAmount": { "value": 831.60, "currency": "AUD" }
          },
          "errorDetails": {
            "errorSeverityCode": "ERROR",
            "errorDescription": "No longer a member of superannuation entity",
            "errorDetailedDescription": "Please check the USI to confirm that the number is correct. See {url} for more information."
          }
        }
      },
      "memberResponseDetails": null
    }
  ]
}
```

### Response Types

`responseType` on `employerResponse.responseType` or `memberResponse.responseType`:

| Value | Meaning |
|---|---|
| `NON_REFUND` | Contribution accepted by the fund — no refund issued |
| `EMPLOYER_REFUND` | Entire contribution refunded to employer (e.g. fund rejected it) |
| `MEMBER_REFUND` | Contribution refunded for a specific member |
| `MEMBER_CONTRIBUTION_TYPE_REFUND` | A specific contribution type refunded for a member (e.g. personal contributions amount) |

### Error Severity Codes

`errorSeverityCode` on `errorDetails.errorSeverityCode`:

| Value | Meaning |
|---|---|
| `ERROR` | Hard error — contribution rejected or refunded |
| `WARNING` | Accepted with a warning (e.g. minor data issue noted by fund) |
| `INFORMATION` | Accepted; informational note only |
| `Response` | Standard response acknowledgement |
| `Partial` | Partial acceptance |
| `Progressive` | Progressive/interim status |

```json

  "refundData": null,
  "errorDetails": null
}
```

### Request Parameters

<ParamField path="transactionId" type="string" required>
  Transaction ID from the contribution submission
</ParamField>

### Responses

| Code | Description |
|---|---|
| `200` | Detailed transaction response retrieved successfully |
| `400` | Invalid transaction ID. |
| `401` | Unauthorized - Invalid authentication credentials |
| `404` | Transaction not found |
