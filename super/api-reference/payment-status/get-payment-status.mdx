---
title: "Get payment status"
description: "Retrieves the payment status for a specific transaction by transaction ID. This endpoint allows you to check the current status of a payment that was submitted through the contribution submission endpoint."
api: "GET https://qa-super.mygigsters.com.au/v1/payments/paymentstatus/transaction/{transactionId}"
---

### Use Case

- Check payment status after submitting a contribution
- Monitor payment processing progress
- Verify if a payment has been completed or failed
- Track payment status for reconciliation purposes

### Transaction ID

The transaction ID should be the server-generated transaction ID (in format `txn-{uuid}`) that was returned when submitting the contribution via the `/v1/contributions/contribution` endpoint.

### Overall Payment Status (paymentOverview.paymentStatus)

- **EMPLOYER_PAYMENT**: Payment is in employer payment stage
- **FUND_PAYMENT**: Payment is in fund payment stage
- **PAYMENT_COMPLETE**: Overall payment is complete

### Transaction Payment Status (paymentTransaction[].paymentStatus)

- **PENDING**: Payment is queued and awaiting processing
- **PROCESSING**: Payment is currently being processed
- **COMPLETED**: Payment has been successfully processed
- **SOURCE_FAILED**: Source payment (employer) failed
- **SOURCE_CANCELLED**: Source payment was cancelled
- **DESTINATION_FAILED**: Destination payment (fund) failed
- **DESTINATION_CANCELLED**: Destination payment was cancelled

### Request Parameters

<ParamField path="transactionId" type="string" required>
  Server-generated transaction ID from the contribution submission (format: txn-\{uuid\})
</ParamField>

### Responses

| Code | Description |
|---|---|
| `200` | Payment status retrieved successfully |
| `400` | Bad request - The transaction ID format is invalid or the request could not be processed. |
| `401` | Unauthorized - Invalid authentication credentials |
| `404` | Transaction not found |
| `500` | Internal server error - An unexpected error occurred. If this persists, contact SuperChoice support with your transaction ID. |

### Response fields

<ResponseField name="identifier" type="object">
  Request identifier for tracking the payment status

  <Expandable title="properties">
    <ResponseField name="transactionId" type="object">
      Transaction identifier object
    </ResponseField>

    <ResponseField name="timeInUTC" type="number">
      Timestamp when the request was initiated, expressed as Unix epoch time in milliseconds
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="paymentOverview" type="object">
  Overview of the payment including source and target information

  <Expandable title="properties">
    <ResponseField name="source" type="object">
      Payment source details
    </ResponseField>

    <ResponseField name="targets" type="array">
      List of target superannuation funds for the payment
    </ResponseField>

    <ResponseField name="paymentStatus" type="string">
      Overall payment status
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="paymentTransaction" type="array">
  Array of payment transactions associated with this payment
</ResponseField>

<Accordion title="Error response fields">

<ResponseField name="success" type="boolean">
  Always false for error responses, indicating the operation did not succeed.
</ResponseField>

<ResponseField name="statusCode" type="integer">
  HTTP status code indicating the type of error. Common values: 400 (Bad Request), 401 (Unauthorized), 404 (Not Found), 500 (Server Error)
</ResponseField>

<ResponseField name="message" type="string">
  Human-readable error message explaining what went wrong.
</ResponseField>

</Accordion>
