### Cancellation Window

| Payment `status` | Can cancel? |
|---|---|
| `SUBMITTED` — debit not yet initiated | No — clearing house rejects (error 4024) |
| `EMPLOYER_PAYMENT` — debit initiated, not yet cleared | **Yes** |
| `DEBIT_CLEARED` or later | No — money has already moved |
| `FUNDS_IN_TRANSIT`, `AWAITING_FUND_RESPONSE`, or any terminal status | No — too late |

### After a Successful Cancellation

On a `202 Accepted` response:

- All payment records for this `transactionId` are immediately updated to `CANCELLED` status.
- A `payment.status_changed` webhook is fired for each affected record.
- No further status transitions will occur for this transaction.

### Error 4024

If the clearing house cannot cancel the transaction (payment is outside the cancellation window), it returns error code `4024`. Check the current `status` of the payment records via the [Contribution History](/super/api-reference/contributions/get-contribution-history) endpoint before attempting cancellation.

### Request Parameters

<ParamField path="transactionId" type="string" required>
  The clearing house transaction ID returned when the contribution batch was submitted.
</ParamField>

### Responses

| Code | Description |
|---|---|
| `202` | Cancellation accepted. All payment records for this transaction are immediately updated to CANCELLED and a payment.status_changed webhook is fired for each record. No response body is returned. |
| `400` | Cancellation rejected — the payment is not in a cancellable state. This typically means the debit has already cleared or the transaction has not yet been initiated. The clearing house returns error code 4024. |
| `401` | Unauthorized - Invalid authentication credentials |
| `404` | Transaction not found — no contribution batch exists for the provided transactionId |
| `500` | Internal server error |
