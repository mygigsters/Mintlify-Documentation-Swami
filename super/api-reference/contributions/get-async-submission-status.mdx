---
title: "Get Async Submission Status"
description: "Get the current status of an async contribution submission by the transactionId returned from POST /v2/contributions. The response has the same shape as the data of the contribution.submission_completed webhook, so you can..."
api: "GET https://qa-super.mygigsters.com.au/v2/contributions/{transactionId}"
---

`status` moves `ACCEPTED` → `PROCESSING` → `SUBMITTED`, `FAILED` or `UNDER_REVIEW`. See the [Async Submission (v2)](/super/guides/async-submissions) guide for what each status means and when it is safe to resubmit.

Once `SUBMITTED`, track the payments themselves with the [Payment Status](/super/api-reference/payment-status/get-payment-status) endpoints, exactly as for v1 transactions.

### Request Parameters

<ParamField path="transactionId" type="string" required>
  The transactionId returned by POST /v2/contributions
</ParamField>

### Responses

| Code | Description |
|---|---|
| `200` | Submission found |
| `401` | Unauthorized — invalid authentication credentials |
| `404` | No submission with this transactionId exists for your client |
