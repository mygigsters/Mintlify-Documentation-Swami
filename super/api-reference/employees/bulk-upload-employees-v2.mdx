---
title: "Bulk upload employees (v2)"
description: "Upload a CSV file to onboard multiple employees at once. Identical to POST /v1/employees/bulk-upload, with one difference: this endpoint automatically triggers MVR (Member Verification) for every successfully-created row that..."
api: "POST https://qa-super.mygigsters.com.au/v2/employees/bulk-upload"
---

Maximum 500 rows per upload, 200 KB file size — split larger files into batches.

Rows that pass all validation are saved and get MVR auto-triggered. Rows with missing or invalid fields are returned in `partialRecords` (no MVR is attempted for these until they're completed). Duplicate records are returned in `failedRecords`.

### Responses

| Code | Description |
|---|---|
| `200` | Upload summary |
| `400` | No file uploaded or file is not valid CSV |
| `401` | Unauthorized |

### Response fields

<ResponseField name="bulkUploadId" type="string">
  ID of the bulk upload session record
</ResponseField>

<ResponseField name="uploaded" type="integer">
  Number of employees successfully uploaded (MVR auto-triggered for those with a fund identity)
</ResponseField>

<ResponseField name="partial" type="integer">
  Number of rows saved as partial (missing required fields) — no MVR attempted yet
</ResponseField>

<ResponseField name="failed" type="integer">
  Number of rows that failed outright (duplicate, or missing email)
</ResponseField>

<ResponseField name="uploadedRecords" type="array">
  Successfully created employee records, each including the current mvrStatus/mvrStatusReason — see the Create Employee response above for the full shape.
</ResponseField>

<ResponseField name="partialRecords" type="array">
  Rows saved as partial employees pending self-completion via magic link
</ResponseField>

<ResponseField name="failedRecords" type="array">
  Details of outright-failed rows (duplicate, or missing email)
</ResponseField>
