---
title: "Onboard Employer"
description: "Onboards a new employer to the system. This endpoint creates a new employer record with company details, contact information, address, and payment account configuration."
api: "POST https://qa-super.mygigsters.com.au/v1/employers/onboard"
---

<Tip>
  **Why it's useful:** Use it to set up the employer of record, including the bank account contributions are debited from.
</Tip>

### Important Notes

- **Contact Email Uniqueness**: `contactPerson.emailAddress` must be unique among your employers (case-insensitive). If another of your employers already uses this email, the request is rejected with `400` (error code `4003`).
- **ABN Validation**: The ABN is validated in two stages - a format check (exactly 11 digits) and the ATO checksum algorithm. A syntactically-correct but non-existent ABN (e.g. 34623710897) is rejected.
- **Contact Area Code**: `contactPerson.areaCode` must be one of the valid Australian landline area codes: 02, 03, 04, 07, 08.
- **Required Information**: All company details, contact person information, addresses, and payment accounts must be provided.
- **Direct Debit Agreement**: The direct debit agreement terms must be accepted to complete onboarding.

### Use Case

- Onboard a new employer for superannuation contributions
- Configure payment accounts for contributions and refunds

### Request Body

<ParamField body="companyDetails" type="object" required>
  Company and employer details
</ParamField>

<ParamField body="contactPerson" type="object" required>
  Contact person details for the employer
</ParamField>

<ParamField body="companyAddress" type="object" required>
  Company postal address
</ParamField>

<ParamField body="directDebitAccount" type="object" required>
  Bank account details for direct debit payments
</ParamField>

<ParamField body="refundAccount" type="object" required>
  Bank account details for refunds
</ParamField>

<ParamField body="directDebitAgreement" type="object" required>
  Direct debit agreement acceptance
</ParamField>

<ParamField body="legalAgreements" type="object">
  Optional. Legal agreement acceptances. All fields are required if this object is provided.
</ParamField>

<ParamField body="digitalSignature" type="string">
  Optional. Base64-encoded PNG of the employer's digital signature collected during onboarding.
</ParamField>

### Responses

| Code | Description |
|---|---|
| `201` | Employer onboarded successfully |
| `400` | Bad request - Invalid employer data or validation error, or contact email already used by another of your employers (errorCode 4003) |
| `401` | Unauthorized - Invalid authentication credentials |
| `500` | Internal server error - An unexpected error occurred. If this persists, contact support. |

### Response fields

<ResponseField name="employerId" type="string">
  Unique identifier for the onboarded employer
</ResponseField>

<ResponseField name="clientId" type="number">
  Client ID associated with this employer
</ResponseField>

<ResponseField name="message" type="string">
  Success message
</ResponseField>

<ResponseField name="onboardedAt" type="string">
  Timestamp when the employer was onboarded
</ResponseField>

<Accordion title="Error response fields">

<ResponseField name="success" type="boolean">
  Always false for error responses, indicating the operation did not succeed.
</ResponseField>

<ResponseField name="statusCode" type="integer">
  HTTP status code indicating the type of error. Common values: 400 (Bad Request), 401 (Unauthorized), 500 (Server Error)
</ResponseField>

<ResponseField name="message" type="string">
  Human-readable error message explaining what went wrong. May include specific details about which field or value caused the error. Examples include "Invalid ABN format", "ABN failed the ATO checksum validation", and "Area code must be one of '02', '03', '04', '07', '08'".
</ResponseField>

<ResponseField name="errorCode" type="integer">
  Superannuation clearing house-specific error code for programmatic error handling. Refer to the error code reference documentation for a complete list of codes.
</ResponseField>

</Accordion>
