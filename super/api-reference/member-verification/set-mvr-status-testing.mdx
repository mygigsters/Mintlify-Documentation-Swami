---
title: "Set MVR status (testing)"
description: "Forces mvrStatus onto an employee **without a real SuperChoice submission** — intended for QA/testing environments, where real funds never reply, so you can still exercise every status/webhook outcome your integration needs to..."
api: "PATCH https://qa-super.mygigsters.com.au/v2/mvr/employee/{employeeId}"
---

Setting a status this way also permanently exempts the employee from the MVR payment gate (the same effect as `PATCH /v2/mvr/employee/:employeeId/override`) — if a real fund response later arrives for this employee, it only updates `mvrStatus`/`mvrStatusReason` for visibility and never blocks payment again. Fires the `employee.mvr_status_changed` webhook for any terminal status (`VERIFIED`, `WARNING`, `REJECTED`, `NOT_SUPPORTED`, `TIMED_OUT`) — never for `PENDING`, matching the real flow.

Requires the employee to already have a fund identity (`usi`/`smsf`) set and a qualifying employer for the client — the same preconditions a real `POST /v2/mvr/submit` has, so the fabricated outcome stays realistic.

> **Note:** this endpoint is not environment-restricted — it works in production too. Use it deliberately; it bypasses the real fund check entirely.

### v1 is unaffected

You do not need to adopt the [Employees v2](/super/api-reference/employees/create-employee) endpoints to use this, and `v1` never forces MVR onto anything — keep using `v1` for employees you don't want MVR on at all, and opt specific employees into MVR (via `v2`, or this endpoint) whenever you're ready to.

### Request Body

<ParamField body="status" type="string (PENDING, VERIFIED, WARNING, REJECTED, TIMED_OUT, NOT_APPLICABLE, NOT_SUPPORTED, NOT_CHECKED)" required>
  The mvrStatus to force onto this employee. Setting this also permanently exempts the employee from the MVR payment gate — if a real fund response later arrives for this employee, it only updates mvrStatus/mvrStatusReason for visibility and never blocks payment.
</ParamField>

<ParamField body="reason" type="string">
  Human-readable reason to store as mvrStatusReason, as if the fund had supplied it.
</ParamField>

<ParamField body="employerId" type="string">
  Optional explicit employerId override — see POST /v2/mvr/submit's employerId.
</ParamField>

### Responses

| Code | Description |
|---|---|
| `200` | Status forced successfully |
| `400` | Bad request — the employee has no fund identity (usi/smsf), or no employer at the client is onboarded and synced at the clearing house |
| `401` | Unauthorized — invalid authentication credentials |
| `404` | Employee not found for this client |

```java Java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.util.Base64;

public class Example {
    public static void main(String[] args) throws Exception {
        String credentials = Base64.getEncoder()
            .encodeToString("apiUsername:apiPassword".getBytes());

        String body = String.join("\n",
            "{",
            "  \"status\": \"REJECTED\",",
            "  \"reason\": \"Member not found with supplied information.\"",
            "}"
        );

        HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create("https://qa-super.mygigsters.com.au/v2/mvr/employee/6a58c9406820b9ff62b527b3"))
            .header("Authorization", "Basic " + credentials)
            .header("Content-Type", "application/json")
            .method("PATCH", HttpRequest.BodyPublishers.ofString(body))
            .build();

        HttpResponse<String> response = HttpClient.newHttpClient()
            .send(request, HttpResponse.BodyHandlers.ofString());

        System.out.println(response.body());
    }
}
```
