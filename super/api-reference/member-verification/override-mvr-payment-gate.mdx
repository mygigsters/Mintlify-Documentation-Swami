---
title: "Override MVR payment gate"
description: "Exempts (or restores) a single employee from the MVR payment gate — **without changing their mvrStatus**mvrStatus**. mvrStatus/mvrStatusReason keep updating normally (from the v2 auto-trigger, a manual POST /v2/mvr/submit, or..."
api: "PATCH https://qa-super.mygigsters.com.au/v2/mvr/employee/{employeeId}/override"
---

This is the per-employee counterpart to the account-level MVR exemption some clients are temporarily granted — use this when only specific employees need to bypass the gate (e.g. a fund that reliably times out, or while chasing down a rejection with the fund) rather than the whole account.

Always fires the `employee.mvr_status_changed` webhook, whichever direction you set it — see the [Webhooks](/super/api-reference/webhooks/register-webhook) page.

### v1 is unaffected

You do not need to adopt the [Employees v2](/super/api-reference/employees/create-employee) endpoints to use this — MVR, the payment gate, and this override all only ever apply to employees that have a fund identity set through a `v2` call at some point. Employees created and managed purely through `v1` never have an `mvrStatus` in the first place, so there is nothing for this endpoint to meaningfully act on for them. Adopt `v2` (and MVR) on your own schedule — `v1` keeps behaving exactly as it always has either way.

### Request Parameters

<ParamField path="employeeId" type="string" required>
</ParamField>

### Request Body

<ParamField body="override" type="boolean" required>
  When true, this employee is exempt from the MVR payment gate: mvrStatus/mvrStatusReason keep updating normally as usual (manual or automatic), but contribution submission is never blocked by them, regardless of what the status is or later becomes. Set false to restore normal gating.
</ParamField>

<ParamField body="reason" type="string">
  Optional free-text note on why this override was set, for audit purposes.
</ParamField>

### Responses

| Code | Description |
|---|---|
| `200` | Override updated |
| `400` | Bad request — no employer at the client is onboarded and synced at the clearing house, so there's nowhere to route the resulting webhook delivery |
| `401` | Unauthorized — invalid authentication credentials |
| `404` | Employee not found for this client |

```java Java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.util.Base64;

public class Example {
    public static void main(String[] args) throws Exception {
        String credentials = Base64.getEncoder()
            .encodeToString("apiUsername:apiPassword".getBytes());

        String body = String.join("\n",
            "{",
            "  \"override\": true,",
            "  \"reason\": \"Fund repeatedly times out in QA; unblocking while SuperChoice investigates.\"",
            "}"
        );

        HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create("https://qa-super.mygigsters.com.au/v2/mvr/employee/6a58c9406820b9ff62b527b3/override"))
            .header("Authorization", "Basic " + credentials)
            .header("Content-Type", "application/json")
            .method("PATCH", HttpRequest.BodyPublishers.ofString(body))
            .build();

        HttpResponse<String> response = HttpClient.newHttpClient()
            .send(request, HttpResponse.BodyHandlers.ofString());

        System.out.println(response.body());
    }
}
```
