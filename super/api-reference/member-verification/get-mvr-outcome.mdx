title: "Get MVR outcome"
description: "Look up the stored outcome of an MVR request by its transactionId — the same ID returned by POST /v2/mvr/submit (or found via the Employees v2 automatic trigger). Use this to poll for a result instead of waiting for the..."
api: "GET https://qa-super.mygigsters.com.au/v2/mvr/{transactionId}"
---

`status` starts at `PENDING` and moves to a terminal state (`VERIFIED`, `WARNING`, `REJECTED`, or `TIMED_OUT`) once the fund responds — usually within 24–48 hours. See the [MVR Verification](/super/guides/member-verification) guide for what each status means.

### Request Parameters

<ParamField path="transactionId" type="string" required>
  The transactionId returned by POST /v2/mvr/submit
</ParamField>

### Responses

| Code | Description |
|---|---|
| `200` | MVR request found |
| `401` | Unauthorized — invalid authentication credentials |
| `404` | No MVR request found for this transactionId, or it belongs to a different client |
