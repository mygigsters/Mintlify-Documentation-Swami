This walkthrough takes you through a complete super integration in the demo environment, from creating an API key to tracking a contribution.

<Tip>
  Don't want to build onboarding screens? Steps 3 and 4 can be done with [embedded components](/super/components/overview) instead.
</Tip>

<Steps>
  <Step title="Create an API key">
    Sign in with a one-time passcode and create a key pair. See [Authentication](/super/authentication).
  </Step>
  <Step title="Make your first request">
    Check your credentials by listing your employees.

    ```java Java
    import java.net.URI;
    import java.net.http.HttpClient;
    import java.net.http.HttpRequest;
    import java.net.http.HttpResponse;
    import java.util.Base64;

    public class Example {
        public static void main(String[] args) throws Exception {
            String credentials = Base64.getEncoder()
                .encodeToString("apiUsername:apiPassword".getBytes());

            HttpRequest request = HttpRequest.newBuilder()
                .uri(URI.create("https://qa-super.mygigsters.com.au/v1/employees"))
                .header("Authorization", "Basic " + credentials)
                .method("GET", HttpRequest.BodyPublishers.noBody())
                .build();

            HttpResponse<String> response = HttpClient.newHttpClient()
                .send(request, HttpResponse.BodyHandlers.ofString());

            System.out.println(response.body());
        }
    }
    ```

    ```go Go
    package main

    import (
    	"fmt"
    	"io"
    	"net/http"
    )

    func main() {
    	req, err := http.NewRequest("GET", "https://qa-super.mygigsters.com.au/v1/employees", nil)
    	if err != nil {
    		panic(err)
    	}
    	req.SetBasicAuth("apiUsername", "apiPassword")

    	res, err := http.DefaultClient.Do(req)
    	if err != nil {
    		panic(err)
    	}
    	defer res.Body.Close()

    	data, _ := io.ReadAll(res.Body)
    	fmt.Println(string(data))
    }
    ```

  </Step>
  <Step title="Onboard an employer">
    Create the employer of record with [Onboard employer](/super/api-reference/employers/onboard-employer). This sets up the company details, the contact, and the bank account contributions are debited from. The direct debit agreement must be accepted to complete onboarding. See [Onboard an employer](/super/guides/onboard-an-employer).
  </Step>
  <Step title="Register your freelancers">
    Add each freelancer with [Create employee](/super/api-reference/employees/create-employee). To pre-fill their fund details, search with [SuperSelector](/super/api-reference/funds/superselector), or let them pick from [active funds](/super/api-reference/funds/get-active-superannuation-funds). See [Add employees](/super/guides/add-employees).
  </Step>
  <Step title="Validate before you pay">
    Check each fund's USI with [Validate superannuation fund](/super/api-reference/funds/validate-superannuation-fund). To confirm the fund will accept contributions for that member, use [member verification](/super/guides/member-verification).
  </Step>
  <Step title="Submit a contribution">
    Send the contribution with [Submit contribution](/super/api-reference/contributions/submit-contribution). For large pay runs, use [async submissions](/super/guides/async-submissions).
  </Step>
  <Step title="Track it to the fund">
    Follow the contribution with [Get contribution history](/super/api-reference/contributions/get-contribution-history) and [Get payment status](/super/api-reference/payment-status/get-payment-status), or [register a webhook](/super/api-reference/webhooks/register-webhook) to be notified.
  </Step>
</Steps>

## Handle errors

- Check the status code on every response.
- Fix and resend `4xx` errors. The response body says which field was wrong.
- Retry `5xx` errors with exponential backoff.
